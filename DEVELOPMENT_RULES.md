# Development Rules for AI Agents

## Before every task
Read project docs and relevant files; inspect branch and working changes; understand current architecture; define scope, risks and acceptance criteria; ask before expanding scope.

## Implementation
Work in small reviewable changes. Preserve approved design, copy, references and working features. Never invent company facts, client results, testimonials, team members, prices or provider claims. Avoid unnecessary dependencies. Keep components accessible, responsive and reusable. Keep products modular. Never commit secrets. Do not silently change database, auth or deployment configuration. Prefer progressive enhancement and fast initial rendering. Provide fallbacks for 3D/video/motion. Maintain separately reviewed English and Bangla content.

## Performance
Fast loading is a first-class acceptance criterion. Optimize images, defer heavy modules, lazy-load below-fold media, minimize JavaScript, avoid excessive blur and continuous animation, and test mobile/constrained networks.

## Verification
Run relevant builds/tests where possible; inspect diffs; test affected routes and interactions; report exactly what changed and what was verified. Separate passed, failed and untested. Never claim success without evidence.

## Approval
Ask before major architecture changes, paid services, external integrations, security-sensitive decisions, destructive actions, production database changes and production releases.

## Phone-first collaboration
Owner reviews on a phone. Provide preview URLs, concise review instructions and clear screenshots. Do not require local terminal use when a connected cloud workflow can safely perform the task.
